# 07 — Security threat model

**A deck is hostile until proven otherwise.** It comes from email, from strangers, and from people
trying to reach the next person who opens it. Every threat here has a control and a named test. A
limit without a test seen to fail is not a control.

Status: **Tested** means a test exists and was seen red without the fix. **Planned** names where it
lands; some planned rows have partial code, and only Tested rows may be relied on. **Partial** means a control exists but no test proves all of it.

**Outcome changed by ADR-015 ([29](29-RECOVERY.md)).** The control in each row stands, and the attack is still stopped. Its default outcome is: neutralize it, set aside what is affected, and open the rest of the deck. Only `strict: true` (`PresentationPackage::open_strict`) refuses, and with the code the row has always had; each hostile fixture's manifest row names that code and what recovery reports (`every_fixture_meets_its_expectation`). "Refused" below means under `strict`; "Default" says what happens otherwise. Every hostile fixture stays, and `every_hostile_fixture_opens_and_says_what_was_done` and `every_hostile_fixture_can_be_edited_into_a_valid_file` hold all of them to "opens, the attack did nothing, and an edit writes a file F4 passes".

## Package

| SEC-P01 | Zip bomb by ratio or total size | Admission caps; `rejects_zip_bomb_by_expansion_ratio`, `rejects_expansion_over_total_cap`. | SEC-P02 | Forged sizes: part produces more than it declared | Bytes held to the declaration. **The `zip` crate enforces this first**: since version 9 it stops a read past the declared size, and `read_part` maps that error to `CS-PKG-0003` (`a_part_that_produces_more_than_it_declared_is_refused`). ## Encrypted and signed files

Password-protected decks are a Compound File wrapping an encrypted package ([MS-OFFCRYPTO]). The CFB
reader is a new hostile-input parser with its own fuzz target and limits. The password is never logged
or sent to a server, and decryption runs in the client. Editing a signed deck invalidates its signature,
so the user is told and the signature parts are dropped explicitly, in the report, not silently.

## Standing rules

- **Resource exhaustion ends in a stopped part or a clean refusal,** never a crash, hang or OOM.
- **Copied code is held to this document.** `SEC-P04` to `SEC-P07` arrived with OpenCalc's crate.
- **A fuzz target accompanies every parser,** and a crash found by one becomes a fixture.
- **A bound is never quietly lowered in prose.** A contract the code does not keep is a tracker row.
