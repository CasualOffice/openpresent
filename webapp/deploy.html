Self-host

Serve OpenPresent from your own site.

The editor is static files and one WebAssembly engine. There is no server component: a deck is opened and drawn in the visitor's own browser and never sent anywhere, so any web server or static host will do.

Two minutes

With Rust (the version in rust-toolchain.toml) and wasm-pack installed:

# 1. build the engine into the editor's folder
git clone https://github.com/CasualOffice/openpresent
cd openpresent
wasm-pack build crates/casual-slide-wasm --release --target web --out-dir ../../webapp/pkg

# 2. serve the folder, over HTTP, from anything
python3 -m http.server -d webapp 8080

# 3. open http://localhost:8080/editor.html and drop a .pptx on it

The out-dir is relative to the crate, so ../../webapp/pkg lands in the repository's webapp/pkg.

What the files are

FileWhat it is
editor.htmlThe editor. This is the only page a self-hosted install needs
editor*.js, commands.js, ribbon*.jsThe editor's modules: the command registry, the ribbon, the slides and the dialogs
render.worker.jsA module worker that runs the engine off the page's main thread
editor.css, ribbon.css, ribbon.tokens.css, icons.fluent.svgThe editor's look and icons. The sprite is fetched at run time, so it must be served too
pkg/casual_slide_wasm.js, pkg/casual_slide_wasm_bg.wasmThe engine, built by wasm-pack
index.html, docs.html, deploy.html, download.html, style.css, site.jsThis website. Leave them out if you only want the editor

Build the engine

The engine is the crate casual-slide-wasm, compiled to wasm32-unknown-unknown. Build it in release mode, with --target web so it loads as an ES module with no bundler. CI builds it the same way, with wasm-pack 0.14.0.

Headers and CSP

  • Serve over HTTP or HTTPS, not file://: the editor is ES modules and a module worker, which browsers do not load from disk.
  • Serve .wasm as application/wasm. Most servers do; an old one may need the type added.
  • Every page carries its own Content Security Policy in a <meta> tag. If you send one as a header too, the browser applies both, so the header must allow at least script-src 'self' 'wasm-unsafe-eval', worker-src 'self', connect-src 'self', style-src 'self', font-src 'self' and img-src 'self' blob: data:.
  • No cookies, no storage of documents and no requests to any other origin: the editor needs nothing else.

Any path, any host

Every link and import is relative, so the folder works at the root of a domain or under any path, such as https://example.com/tools/present/editor.html. Nothing needs configuring.

Size and compression

The engine is the large file, most of it the fonts it lays text out with, so every visitor sees the same line breaks. Serve it compressed, with gzip or Brotli. Splitting the fonts out of the engine is tracked work.

How this site is deployed

This site is GitHub Pages, published by the workflow pages.yml on every push to main, the way OpenCalc publishes its own. It builds the engine with wasm-pack, copies webapp/ to the root of the site with the engine in pkg/, draws the slide pictures on the front page with our renderer, adds the slide gallery under gallery/, and deploys the lot. Copying the same steps into your own CI is a good way to self-host.

What is not here yet

  • No collaboration server. Co-editing comes later, with a server you run yourself, as OpenCalc's does.
  • No container image or package. Build from source as above.
  • No SDK for embedding the editor in your own page. Serve editor.html as it is, or link to it.
