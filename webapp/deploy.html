Self-host

Serve the viewer from your own site.

The viewer is static files. There is no server component: a deck is opened in the visitor's browser and never sent anywhere.

Build

With Rust (the version in rust-toolchain.toml) and wasm-pack:

wasm-pack build crates/casual-slide-wasm --release --target web --out-dir "$PWD/webapp/pkg"

Then publish the webapp/ folder, with pkg/casual_slide_wasm.js and pkg/casual_slide_wasm_bg.wasm in it. The GitHub workflow gallery.yml does exactly this for the project's own site.

Serve

  • Over HTTP or HTTPS, not file://: the page is ES modules and a module worker.
  • Serve .wasm as application/wasm.
  • The page carries its own Content Security Policy. If you send one as a header too, it must allow script-src 'self' 'wasm-unsafe-eval', worker-src 'self', connect-src 'self' and img-src 'self' blob:.

The engine is about 16 MB, most of it the fonts it lays text out with, so every visitor sees the same line breaks. Serve it compressed; a smaller split is tracked.
